# TrustMesh

TrustMesh 是一个纯进程内存的 Go 库，用于机构节点之间在没有中心身份
提供方的情况下完成双向身份挑战。报文的传输由调用方负责。

## 用法

```go
// 每个节点持有自己的 Ed25519 私钥和固定的可信 DID -> 公钥映射。
node := trustmesh.NewNode(selfDID, privKey, trustedPeers)

// 发起挑战（第一步）：把返回的报文交给对端。
invite, err := node.Initiate(peerDID)

// 收到对端报文：返回需要回发的报文（可能为 nil，表示无需回复）。
resp, _ := node.Receive(inbound)

// 查询会话与对端状态。
info, ok := node.Session(sessionID)
status := node.PeerStatus(peerDID)
```

## 协议

三步握手，会话标识与双方 nonce 均为 256 位密码学安全随机值：

1. 发起方发送 `MsgInvite`（会话标识 + nonceA）。
2. 响应方接受后返回 `MsgResponse`（nonceB + 响应方 Ed25519 证明）。
3. 发起方验证后返回 `MsgConfirm`（发起方证明）并本地成功；响应方
   验证最后的证明后才本地成功。

两份证明都绑定了协议用途、双方 DID、签名方角色、会话标识与两枚
nonce，无法跨会话、跨方向或跨对端重放。

## 语义

- 双方各自从本地起点计时（发起方自创建会话、响应方自接受邀请），
  须在严格小于 10 秒内完成本地认证，恰到 10 秒即超时；只承诺本地结果。
- 会话终态（成功/失败/取消/过期）不可反转，每个会话最多结算一次。
- 完全相同的合法重传返回该步骤原输出，不更换 nonce、不延长时限、
  不重复结算；邀请重传不会创建第二个会话。
- 签名或绑定内容不符、到期未完成各结算一次失败；同一对端连续 5 次
  失败立即封禁 30 分钟，一次成功清零计数。
- 封禁立即取消该对端其余未结束会话（不计失败），期间拒绝新发起并
  丢弃其全部入站报文；到期自动解封并清零计数。
- 使用本机单调时间，所有到期事件在每个操作前按其原截止时刻结算，
  同刻超时按会话标识字节序结算。测试可用 `WithClock` 注入时钟。
